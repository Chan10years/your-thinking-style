# YourThinkingStyle 分析前工作区设计

## 范围

仅重构 `/analyze` 的分析前界面。保留首页、分析请求、输入校验、DeepSeek API、Schema 与服务端逻辑。暂不修改分析结果页面，不加入代码运行能力。

## 页面结构

- 首页继续作为品牌入口，主要入口文案统一为“开始分析”，进入 `/analyze`。
- 工作区顶部为 60px 左右的平直工具栏。
- 桌面主体占满工具栏以下视口，外层不滚动，面板内部独立滚动。
- 主体左侧 45%，右侧 55%，以 1px 线分隔。
- 右侧上部 58% 为 Monaco C++ 编辑器。
- 右侧下部 42%，左栏 45% 为“我的思路或卡点”，右栏 55% 为“失败案例”标签面板。

## 顶部工具栏

- 左侧复用 `Think / YourThinkingStyle` 品牌标识。
- 右侧依次为 API Key 配置、主题选择、黑底白字“开始分析”。
- API Key 通过轻量弹层配置，仍只保存在当前 React 内存，不持久化、不记录日志。
- 主题支持“跟随系统 / 浅色 / 深色”。主题偏好可以持久化，但 API Key 不能。

## 输入面板

### 题目描述

- 保留 `problem` 字段、6000 字限制、校验与计数。
- 输入区域填满左栏，不使用卡片嵌套。
- 占位文字为“粘贴题目描述、限制条件与示例”。

### 代码

- 使用 Monaco Editor，语言固定为 C++。
- 保留 `code` 字段、12000 字限制、状态更新与校验。
- 浅色和深色页面分别使用自定义低对比度 Monaco 主题。

### 我的思路或卡点

- 保留 `userThought`、800 字限制和独立滚动。
- 占位文字为“从哪里开始、如何推导、目前卡在哪里”。
- 在右下区域中占 45%，视觉标题权重高于失败案例。

### 失败案例

- 使用三个文本标签切换 `failureInput`、`expectedOutput`、`actualOutput`。
- 切换时不卸载或合并状态，三个字段继续独立保存。
- 保留原有 2000 / 1000 / 2000 字限制和错误提示。

## 视觉系统

- 浅色：暖白背景、白色表面、黑棕文字、极细灰线。
- 深色：近黑背景、深灰表面、柔白文字、低对比度边线。
- 无渐变、霓虹、玻璃拟态、厚重卡片和大面积阴影。
- 标题栏统一高度，圆角 0–4px。
- 中文展示标题使用现有编辑感衬线字体；工具文字使用 Inter / IBM Plex Mono。
- 焦点使用细边线加深，不使用蓝色光圈。

## 响应式

- 1440×900 与 1920×1080：完整 45/55 双栏与右下双栏。
- 中等宽度：主体比例允许调整，右下双栏可变为上下结构。
- 手机：工具栏换行，面板纵向排列，允许页面滚动。

## 状态与错误

- 点击任一“开始分析”均提交同一个表单。
- API Key 缺失时打开 API Key 弹层并显示现有校验信息。
- 其他字段错误在对应面板标题和字段下方显示。
- 请求中禁用主按钮并显示“分析中…”。
- 成功与服务端错误沿用现有状态逻辑。

## 验收

- 所有七个输入字段保留。
- Monaco 跟随主题。
- 失败案例三个标签保留独立内容。
- API Key 不进入 localStorage、sessionStorage、日志或文件。
- `npm run lint`、`npm run build` 与项目全部测试通过。
- Chrome 验证桌面、窄屏、主题切换、标签切换和 API Key 弹层。
