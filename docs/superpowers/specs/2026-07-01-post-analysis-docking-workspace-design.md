# Post-analysis Docking Workspace Design

## Scope

阶段 5 完成分析后的结果工作区。它分为两个内部阶段：

* 5A：完成分析后三栏结果页和诊断内容完整渲染。
* 5B：完成第三栏轻量 Docking，包括排序、合并、分栏、尺寸调整和恢复默认布局。

阶段 5 不实现 Monaco 红蓝标注、不实现代码与诊断点击联动、不运行代码、不编译、不判题、不修改 DeepSeek Schema。

## Outer Layout

分析成功后，页面从分析前工作区切换为固定三栏：

1. 原始题目。
2. 用户代码。
3. AI 诊断工作区。

外层三栏可沿用现有工作区的线性、低装饰视觉语言。三栏是分析后页面的稳定骨架，诊断模块只能在第三栏内部移动，不能拖到题目栏或代码栏。

补充信息入口在分析后仍保留，至少能展开查看用户原始填写的“我的思路或卡点”。填写过失败输入、预期输出、实际输出或报错时，一并显示；未填写时不占用主要注意力。

## Code Column

中间用户代码区域仍是代码标注的归属位置。阶段 5 只展示用户代码和分析返回的代码相关摘要，不渲染 Monaco 红蓝标注。

第六阶段再处理：

* 蓝色核心算法块标注。
* 红色明确错误标注。
* exactCode 程序化定位。
* 代码与诊断点击联动。

## Diagnostic Modules

AI 诊断工作区默认包含三个模块：

* 思路还原。
* 错误解释。
* 修正方向。

默认布局是一个标签组，标签顺序为“思路还原 / 错误解释 / 修正方向”，默认选中“思路还原”。

### 思路还原

展示 `thoughtRestoration`：

* 分类结论。
* 用户思路摘要。
* 代码实际行为。
* 思路与代码一致性。
* 偏离点。
* 是否能沿原思路修正。
* 判断依据和置信度。

用户未填写思路时，明确说明分析基于代码结构静态推断，可能不完整。

### 错误解释

展示 `redErrors`：

* 按模型返回编号逐条展示 `错误 1` 到 `错误 5`。
* 每条展示错误类型、证据来源、标题、解释、后果和局部修正建议。
* 红色错误为空时显示空状态：未发现可确认的明确错误。当前分析不代表代码一定正确，建议结合测试用例验证。
* `redErrorsUnavailableReason` 非空时显示无法可靠定位具体代码范围的原因。

`suspectedIssues` 作为证据不足或待验证内容展示在错误解释之后或思路还原的辅助区，不进入红色编号体系，不生成橙色标注。

### 修正方向

展示 `fixDirection`：

* 顶部提示用户先看错误解释更容易理解。
* 分开展示 `personalizedPath` 和 `standardPath`，不得合并成一个答案。
* 展示路径策略、步骤、关键算法或数据结构、可达到等级、局限和相对优势。
* 展示 `newKnowledgeNeeded`，按模型返回顺序排列。
* 所有参考代码默认折叠，折叠状态由前端决定，不由模型决定。

## Docking Interaction

“类似 UE5”只指 AI 诊断工作区内部的面板组织和拖拽体验，不复刻完整 UE5 编辑器。

诊断工作区需要支持：

* 标签拖动排序。
* 多个模块合并为同一标签组。
* 模块拖到上、下、左、右形成分栏。
* 拖动分隔线调整尺寸。
* 恢复默认布局。
* 当前页面会话内维护布局状态。

诊断工作区暂不支持：

* localStorage 跨刷新持久化。
* 浮动面板。
* 独立浏览器窗口。
* 模块拖出第三栏。
* 关闭或删除模块。
* 多套布局。
* 完整移动端 Docking。

## Technical Direction

阶段 5B 优先采用成熟 React Docking 布局库，而不是手写完整 Docking 引擎。首选评估 `dockview` / `dockview-react`，因为它支持 IDE-like 标签组、拖拽、边缘停靠和布局序列化。若实际接入成本或 Next.js 兼容性不合适，再评估 `flexlayout-react`。

Docking 布局状态只保存在当前 React 页面生命周期中。刷新页面后恢复默认布局，不写入 localStorage。

## Data Flow

1. 用户点击“开始分析”。
2. `/api/analyze` 返回 `success: true` 和 `data`。
3. 页面保存 `AnalysisResponse` 到 React state。
4. 分析后结果页读取同一份 `AnalysisResponse`。
5. 诊断模块只接收结构化数据和回调，不持有 API Key。
6. 修改题目、代码或补充信息后，旧分析结果必须被清除或显式标记为过期，避免旧诊断与新输入混合。

## Visual Direction

保持现有工作区的暖白 / 近黑双主题、细线分隔、低装饰、编辑器式信息密度。

Docking 标签和分隔线应像工具面板，不像营销卡片。标签需要可读、紧凑、可拖拽；分隔线命中区域可以宽于可见线条。恢复默认布局是诊断工作区内的明确按钮。

## Verification

阶段 5A 验证：

* 分析成功后显示三栏结果页。
* 页面显示思路还原、错误解释、修正方向完整内容。
* 红色错误为空时显示指定空状态。
* `redErrorsUnavailableReason` 能展示。
* `personalizedPath`、`standardPath`、`newKnowledgeNeeded` 分开展示。
* 参考代码默认折叠。
* 补充信息入口保留。

阶段 5B 验证：

* 默认三个模块在同一标签组，默认选中“思路还原”。
* 标签可以拖动排序。
* 模块可以合并到同一标签组。
* 模块可以拖到上、下、左、右形成分栏。
* 分隔线可以调整尺寸。
* 恢复默认布局后回到初始标签组。
* 刷新页面后不恢复上一次布局。
* 模块不能关闭、删除、浮动、弹出或拖出第三栏。

完整代码任务完成后必须运行 `npm run lint` 和 `npm run build`。仅更新本文档时不要求运行。
